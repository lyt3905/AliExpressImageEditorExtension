# 手工验证清单（Chrome）

> ⚠️ 本清单**尚未由开发方在真实 Chrome + 已登录 AliExpress 卖家后台中执行**。
> 自动化测试（`npm run test`，23 文件 / 389 个用例）与构建（`npm run build`）已完成并通过。
> `tests/live` 下的 2 个线上用例也已真实跑通（含**并发 6 实测：6/6 成功**），需显式开启才会联网。
> 真实浏览器端到端验证需要你本机的 Chrome 登录态，请按下面步骤执行。

## 0. 准备

```bash
cd C:\Users\lyt39\Documents\GitHub\AliExpressImageEditorExtension
npm install
npm run typecheck
npm run test
npm run build          # 末尾会自动执行 check:dist 校验产物完整性
npm run check:dist     # 如遇 Chrome 加载报错，先单独跑这条
```

> 若 Chrome 报「无法为脚本加载 JavaScript 'content-script.js'」或「清单文件丢失或不可读取」，
> 几乎都是 `dist/` 半成品（构建被中断）或选错目录（选了项目根目录而不是 `dist`）。
> 先执行 `npm run check:dist`，它会直接告诉你缺什么。

## 1. 加载扩展

1. 打开 `chrome://extensions`
2. 右上角开启 **开发者模式**
3. 点击 **加载已解压的扩展程序** → 选择 **`dist`** 目录（**不是**项目根目录）
4. 确认扩展卡片无红色错误；点击 **Service Worker** 链接应打开 DevTools 且无报错

| --- | --- | --- |
| 6.5.18 | 只删一张、删的是第 1 张 | 图片区**恰好少一张**（占用数从 6 变 5 之类）；少掉的是**原来的第 1 张**（商品正面图），其余每一张都还在 |
| 6.5.19 | 重试绝不删第二张 | 若第一次尝试因面板不在本 frame 而换 frame 重试：整个过程**只删过 1 张**。阶段日志里第二次尝试**不应**出现 `DELETE_IMAGE` |
| 6.5.20 | 取消勾选就完全不动图 | 取消「回填前删第 1 张」后回填 → 所有旧图**原样都在**（含第 1 张），新图落在空槽位；若 6 个位全满则报 6.5.7 的错，**不做任何删除** |
| 6.5.21 | 找不到删除图标就停下，不点别的 | 模拟页面改版使删除图标消失 → **红色报错**「…没有找到删除图标，已停止（不会去点别的按钮）。请手动删掉这一张…」，**页面上不产生其它点击**（不得去点商品页任何按钮） |
| 6.5.22 | 点了但图没消失 → 超时并提示确认框 | 出现二次确认框（图仍在）时 → 报 `DELETE_TIMEOUT` 超时并提示**可能弹了二次确认框**；**不得自己去点那个确认**；面板不会被打开 |
| 6.5.23 | 找不到图片区就停，不到处找 | 若 `.imageUploadWrap` 不存在 → 报「页面上没有找到商品图片区…无法确定要删哪一张，已停止」，**不得**到页面别处找同名节点去删 |
| 6.5.24 | 没有旧图时不算错 | 全新商品（一个已占用槽位都没有）勾选删除后回填 → 正常继续，阶段日志写「图片区没有已占用的槽位，无需删除」，**不报错** |
| 6.5.25 | 删图失败时如实告知净损失 | 若删掉第 1 张后上传未确认成功 → 提示必须写明「注意：本次已先删除了原来的第 1 张图（商品正面图），若新图没上传成功需要你手动补回」，**不得**只显示一句失败 |

## 6.6 回填后自动关闭编辑器（10 秒倒计时）

> 10 秒是**下限**，从**点击那一刻**开始算，但回填结束之前**绝不关**。所以下面既有「它确实关了」，
> 也有「回填没跑完时它没关」「它只关了该关的那一个」和「想留下时能留下」。

| # | 检查项 | 预期 |
| --- | --- | --- |
| 6.6.1 | 点击即出现倒计时 | 点「回填到商品页」后，状态条行尾**立刻**出现「将在 N 秒后关闭编辑器」+「取消」按钮，数字每秒递减；不挤压左侧的抠图计数 |
| 6.6.2 | 倒计时期间点「取消」能留下编辑器 | 点「取消」→ 倒计时消失，标签**不再被关闭**；回填结果照常显示在状态条行尾 |
| 6.6.3 | 只关编辑器，绝不关商品页 | 到点后被关掉的只有 `chrome-extension://…/editor/index.html?session=…`；**商品页标签仍在**，且它正是当前活动标签 |
| 6.6.4 | **回填没跑完时不会关**（本次修复点） | 用一张较大的图回填，让本次回填明显超过 10 秒（真机常见 13~25 秒）→ 第 10 秒时编辑器**仍在**，状态条文案变成「回填完成后将自动关闭编辑器」；回填一结束（结果提示出现）标签随即关闭。**不得**出现「结果还没出来页面就没了」 |
| 6.6.5 | 回填很快时也不提前关 | 回填 3 秒内结束 → 编辑器**不会**立刻关，仍等到第 10 秒才关，避免结果一闪而过 |
| 6.6.6 | 失败也照关（按设计） | 让回填必然失败（如取消勾选删除且图片位全满）→ 失败提示出现后编辑器关闭；失败原因同时写在扩展图标悬停提示上 |
| 6.6.7 | 只关本会话的编辑器 | 用同一个 `session` 参数重复打开编辑器（两个标签）后回填 → **两个都被关**；同时开着**另一个会话**的编辑器标签 → 那个**完全不受影响** |
| 6.6.8 | 兜底路径确实生效 | 若 `window.close()` 被忽略（标签仍在），扩展后台应随即按会话 id 关掉它；扩展后台 Console 不应出现未处理的 rejection |

## 6.7 镜像 / 旋转（只作用于选中的那一个图层）

> 先随便选中一个图层（图片或文字）。没选中任何图层时，右栏只有一句提示，**没有**按钮和旋钮。
> 重点看三件事：**只动选中的那一个**、**整段拖动只算一步撤销**、**镜像过的图层缩放后依然镜像**。

| # | 检查项 | 预期 |
| --- | --- | --- |
| 6.7.1 | 只有选中图层时才出现 | 点画布空白取消选择 → 按钮与旋钮消失，只剩「选中一个图层后，可对它镜像 / 旋转」；重新选中后回来 |
| 6.7.2 | 左转 / 右转 90° | 点「右转 90°」→ 图层**绕自身中心**顺时针转 90°；连点 4 次回到原位，角度读数是 `0°` 而**不是** `360°` |
| 6.7.3 | 90° 是「加」不是「跳」 | 先用画布上的旋转手柄拖到约 30°，再点「右转 90°」→ 变成约 120°，**不是** 90° |
| 6.7.4 | 水平 / 垂直镜像 | 点「水平镜像」→ 左右翻转（要用不对称的图案才看得出，例如文字或有方向的玩具）；再点一次完全还原 |
| 6.7.5 | 镜像按钮的点亮状态 | 处于镜像状态时该按钮变色；再点一次后恢复常态 |
| 6.7.6 | 两个轴互不干扰 | 只点「垂直镜像」→ 水平方向没有被翻转；先在画布上拖到约 30° 再点镜像 → 角度读数**不变**，只是沿该轴翻过去 |
| 6.7.7 | 旋钮拖拽 | 按住旋钮拖动 → 图层实时跟着转，旋钮中央的数字同步变化；松手后停在该角度 |
| 6.7.8 | 旋钮 + Shift 吸附 | 按住 Shift 拖 → 角度只落在 15 的整数倍上；松开 Shift 继续拖 → 又能停在任意角度 |
| 6.7.9 | 旋钮双击归零 | 双击旋钮 → 角度回到 `0°`；**本来就 0° 时双击不应产生空撤销记录**（点一次撤销不应「什么都没发生」） |
| 6.7.10 | 旋钮方向键 | 用 Tab 把焦点移到旋钮 → ←/→ 每按一次转 1°，按住 Shift 转 15°；`Home` 归零 |
| 6.7.11 | **整段拖动只算一步撤销** | 拖旋钮转一大圈（中途不松手），松手后按**一次** Ctrl+Z → 直接回到拖动前的角度，**不是**回到中途某个角度 |
| 6.7.12 | 只变换选中的那一个 | 画布上放两个不对称图层，只选中其中一个做旋转 / 镜像 → 另一个**完全不动** |
| 6.7.13 | 文字图层同样可用 | 选中一个文字图层 → 同样能 90° 旋转与镜像（镜像后字形会左右反过来）；「文字属性」面板不受影响 |
| 6.7.14 | **镜像过的图层缩放后依然镜像** | 先「水平镜像」，再拖四角 anchor 缩小 / 放大 → 仍是镜像状态（按钮保持点亮），且缩放没有变成负数 |
| 6.7.15 | 导出结果与预览一致 | 做完一次镜像 + 一次非 90° 旋转后导出 PNG → 800×800 白底，画面与画布上看到的**完全一致** |
| 6.7.16 | 刷新后保留 | 刷新编辑器 → 角度与镜像状态原样恢复（它们在 `aiee:doc:<sessionId>` 里） |
| 6.7.17 | 水印不受影响 | 做任意旋转 / 镜像 → 水印框仍铺满且不跟着转，依旧不可选中 |
| 6.7.18 | 撤销链正常 | 依次做「右转 90° → 水平镜像 → 拖旋钮」→ 连按 3 次 Ctrl+Z 依次退回：旋钮那次、镜像那次、旋转那次 |

## 7. 失败与恢复

| # | 检查项 | 预期 |
| --- | --- | --- |
| 7.1 | 单张失败不影响其他 | 在选项页输错密码后重开编辑器 → 全部失败并显示「重试」；恢复登录后点「重试」可成功（其他图片状态不受影响） |

| 7.4 | 刷新恢复 · 失败项 | 失败图片刷新后仍为失败状态，等待点击「重试」 |
| 7.5 | 刷新恢复 · 进行中 | 上传/处理中刷新 → 复位为排队并自动重新执行 |

## 8. 安全与合规复核（每次改版都应执行）

| # | 检查项 | 预期 |
| --- | --- | --- |
| 8.1 | 扫描 / 抠图 / 导出不碰页面 | 这三段全程 AliExpress 页面无自动点击、无表单提交、无网络写入到 AliExpress。（**例外**：用户显式点击「回填到商品页」时会操作页面，约束见 8.6 / 8.7） |

| 8.4 | 无远程脚本 | Network 面板中没有加载第三方 JS |
| 8.5 | 白名单域 | 插件只请求 aliexpress 图片 CDN、`39.107.244.239`、`*.aliyuncs.com` |
| 8.6 | 回填只在面板内点击（**唯一例外是删图**） | 回填流程只在素材中心上传面板内点击（上传按钮 + 确认上传）；**商品页的「保存 / 发布 / 提交」全程未被点击**。唯一在商品页上的点击是勾选删除时那一个删除图标（见 8.7） |
| 8.7 | 删图是限定范围的，且能说清删了什么 | 勾选「回填前删第 1 张」时**恰好删掉 1 张**（原来的第 1 张），其余旧图完好；取消勾选时**没有任何**删除动作。编辑器提示必须写明删掉的是哪一张（如「商品正面图」），删除失败时写明净损失 |
| 8.8 | 注入脚本来自本包 | 注入到页面的 7 个脚本全部来自 `dist/vendor/aeiir/`（`chrome.scripting.executeScript` 的 `files`），不加载任何远程 JS |
| 8.9 | 无 `web_accessible_resources` | manifest 中确实没有该项 —— 本方案靠 `executeScript` 注入，不需要把文件暴露给页面 |
| 8.10 | 自动关闭的标签范围是受限的 | 回填后 10 秒的自动关闭**只作用于本会话的编辑器页**（按 `editor/index.html` 前缀 + `?session=` 精确匹配）。前后台从未按「当前活动标签」或任意 tab id 关闭，商品页与其它标签不受影响（对应 6.6.3 / 6.6.6） |
