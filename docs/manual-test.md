# 手工验证清单（Chrome）

> ⚠️ 本清单**尚未由开发方在真实 Chrome + 已登录 AliExpress 卖家后台中执行**。
> 自动化测试（`npm run test`，113 个用例 + 1 个线上契约用例）与构建（`npm run build`）已完成并通过。
> 真实浏览器端到端验证需要你本机的 Chrome 登录态，请按下面步骤执行。

## 0. 准备

```bash
cd C:\Users\lyt39\Documents\GitHub\AliExpressImageEditorExtension
npm install
npm run typecheck
npm run test
npm run build          # 末尾会自动执行 check:dist 校验产物完整性
npm run check:dist     # 如遇 Chrome 加载报错，先单独跑这条
```

> 若 Chrome 报「无法为脚本加载 JavaScript 'content-script.js'」或「清单文件丢失或不可读取」，
> 几乎都是 `dist/` 半成品（构建被中断）或选错目录（选了项目根目录而不是 `dist`）。
> 先执行 `npm run check:dist`，它会直接告诉你缺什么。

## 1. 加载扩展

1. 打开 `chrome://extensions`
2. 右上角开启 **开发者模式**
3. 点击 **加载已解压的扩展程序** → 选择 **`dist`** 目录（**不是**项目根目录）
4. 确认扩展卡片无红色错误；点击 **Service Worker** 链接应打开 DevTools 且无报错
5. 若此前已加载过旧版本：改动源码并重新 `npm run build` 后，必须回到本页点击该扩展的
   **刷新（⟳）** 按钮，否则 Chrome 仍在使用旧产物
6. 点击工具栏 🧩 → 把本扩展 **固定（Pin）** 到工具栏（本扩展没有 popup，只能从工具栏图标触发）

| # | 检查项 | 预期 |
| --- | --- | --- |
| 1.1 | 扩展成功加载 | 卡片正常显示，无错误徽标 |
| 1.2 | 权限提示 | 只出现「读取和更改您在 aliexpress.com 等网站上的数据」「管理您的下载内容」等，**不含**「读取和更改您在所有网站上的数据」 |

## 2. 配置服务端

5. 扩展详情 → **扩展程序选项**
6. 填写服务地址（默认 `https://39.107.244.239`）、账号、密码 → 点击 **登录并保存**

| # | 检查项 | 预期 |
| --- | --- | --- |
| 2.1 | 登录成功 | 状态显示为 `<用户名> · <角色>` |
| 2.2 | 密码不落盘 | DevTools → Application → Storage → Local Storage 中**没有**密码字段 |
| 2.3 | 刷新页面后 | 登录状态仍为已登录 |
| 2.4 | 错误提示 | 故意填错密码 → 显示「用户名或密码不正确」 |

## 3. 扫描与打开编辑器

7. 打开 AliExpress 卖家后台的**商品编辑页**（URL 含 `product` / `publish` 等）
8. 点击工具栏插件图标

| # | 检查项 | 预期 |
| --- | --- | --- |
| 3.1 | 扫描主图 | 工具栏图标短暂显示 `…` 徽标 |
| 3.2 | 自动打开 Editor | 新标签页打开 `chrome-extension://<id>/editor/index.html?session=…` |
| 3.3 | 原图立即显示 | 左侧「原始素材」出现所有扫描到的商品图缩略图，**无需等待** |
| 3.4 | **提取范围正确** | 只出现 `.imageUploadWrap` 里**已填图片**的槽位（本例 5 张：正面 / 背面 / 实拍 / 侧面 / 细节）；不含空槽位、悬浮预览副本、SKU 图、详情图、icon |
| 3.5 | **素材名带槽位标签** | 卡片上显示「商品正面图」等页面标签，而不是笼统的「原图」 |
| 3.6 | 未修改页面 | AliExpress 页面内容、商品图片、保存按钮均未变化 |
| 3.7 | 非 AliExpress 页面点击 | 图标显示红色 `!`，悬停提示「当前页面不是 AliExpress 页面」 |

| # | 检查项 | 预期 |

## 7. 失败与恢复

| # | 检查项 | 预期 |
| --- | --- | --- |
| 7.1 | 单张失败不影响其他 | 在选项页输错密码后重开编辑器 → 全部失败并显示「重试」；恢复登录后点「重试」可成功（其他图片状态不受影响） |
| 7.2 | 失败不阻塞导出 | 存在失败图片时仍可正常导出 PNG |
| 7.3 | 刷新恢复 · 成功项 | 抠图成功后刷新编辑器 → 「已抠素材」仍在，**不会重复提交抠图** |
| 7.4 | 刷新恢复 · 失败项 | 失败图片刷新后仍为失败状态，等待点击「重试」 |
| 7.5 | 刷新恢复 · 进行中 | 上传/处理中刷新 → 复位为排队并自动重新执行 |
| 7.6 | 刷新恢复 · 画布 | 已排布的图层在刷新后保留（画布文档持久化） |
| 7.7 | 重复点击不重复提交 | 抠图进行中反复点击插图/切换选择 → 网络面板中不会出现重复的 `background/remove` 请求 |

| # | 检查项 | 预期 |
