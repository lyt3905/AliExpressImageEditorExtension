# 手工验证清单（Chrome）

> ⚠️ 本清单**尚未由开发方在真实 Chrome + 已登录 AliExpress 卖家后台中执行**。
> 自动化测试（`npm run test`，314 个用例）与构建（`npm run build`）已完成并通过。
> `tests/live` 下的 2 个线上用例也已真实跑通（含**并发 6 实测：6/6 成功**），需显式开启才会联网。
> 真实浏览器端到端验证需要你本机的 Chrome 登录态，请按下面步骤执行。

## 0. 准备

```bash
cd C:\Users\lyt39\Documents\GitHub\AliExpressImageEditorExtension
npm install
npm run typecheck
npm run test
npm run build          # 末尾会自动执行 check:dist 校验产物完整性
npm run check:dist     # 如遇 Chrome 加载报错，先单独跑这条
```

> 若 Chrome 报「无法为脚本加载 JavaScript 'content-script.js'」或「清单文件丢失或不可读取」，
> 几乎都是 `dist/` 半成品（构建被中断）或选错目录（选了项目根目录而不是 `dist`）。
> 先执行 `npm run check:dist`，它会直接告诉你缺什么。

## 1. 加载扩展

1. 打开 `chrome://extensions`
2. 右上角开启 **开发者模式**
3. 点击 **加载已解压的扩展程序** → 选择 **`dist`** 目录（**不是**项目根目录）
4. 确认扩展卡片无红色错误；点击 **Service Worker** 链接应打开 DevTools 且无报错
5. 若此前已加载过旧版本：改动源码并重新 `npm run build` 后，必须回到本页点击该扩展的
   **刷新（⟳）** 按钮，否则 Chrome 仍在使用旧产物
6. 点击工具栏 🧩 → 把本扩展 **固定（Pin）** 到工具栏（本扩展没有 popup，只能从工具栏图标触发）

## 6.5 回填到商品页（往图片区放一张新图，默认先删第 1 张）

> 这是**唯一**会主动操作 AliExpress 页面的功能，只在用户点击按钮时发生。
> 红线：只点上传面板内部的「上传图片」与「确认上传」，以及（勾选删除时）第 1 张图上的那一个删除图标，
> **绝不**点商品页的「保存 / 发布 / 提交」。
>
> 工具栏的 **回填前删第 1 张** 默认**勾选**：6 个图片位常是满的，没有空位就无处可放。取消勾选后回填
> 只追加、不动任何旧图。删图发生在**开面板之前**（见 6.5.18 起的专项检查）。

| 6.5.8 | 手动打开面板后可继续（**不能是死循环指引**） | 接着 6.5.7：在商品页**手动**打开素材中心上传面板，再点一次「回填到商品页」→ 流程**复用已开面板**并成功，**不得再报同一个错**；阶段日志有「本 frame 的上传面板已经打开，直接复用，跳过点击上传按钮」 |
| 6.5.9 | 未确认也如实说明 | 若面板消失/没有确认按钮：提示「回填未确认：…」并让人工核对，**不得显示为成功** |
| 6.5.10 | 面板在 iframe 里也能成功 | 若上传面板不在主文档，流程自动换 frame 重试（最多 3 次），最终仍成功 |
| 6.5.11 | 商品页已关闭 | 关掉商品页标签后点回填 → 红色提示「原来的商品页标签已经关闭…」；**页面上不产生任何点击** |
| 6.5.12 | 会话过期 | 清空 `chrome.storage.local` 后点回填 → 「会话已过期，请从商品页重新点击插件图标进入编辑器」 |
| 6.5.13 | 体积上限前置拦截 | 合成一张 >5MB 的图再回填 → 提示超过 5MB 上限，且**面板未被打开、页面未被点击** |
| 6.5.14 | 不做全自动兜底 | 页面改版后若找不到可见上传入口且图片位没满 → 返回明确错误、让用户手动打开面板（打开后再点一次即可继续），**不盲目点击** |
| 6.5.15 | 没有空槽位入口时**拒绝**，绝不覆盖 | 可见上传入口全挂在**已占用**槽位上（或 6 槽全满）→ 直接红色报错，**不得**改点已占用槽位的入口 —— 那会让「确认上传」覆盖旧图（真机踩过）。以单测为准（`page-fill-bridge.test.ts` 的「returns null when every slot is occupied」） |
| 6.5.15a | 真机入口与落点（2026-09-28 新增） | 上传入口是 `div.upload-content`（含「上传图片」文案 + add 图标）；流程只点**最后一个空槽位**的入口，确认上传后新图**追加到末尾**、不覆盖任何旧图 |
| 6.5.15b | 上传完成后面板不卡住（2026-09-28 新增） | 上传成功后面板切到「已添加图片」列表态（拖拽区消失）→ 流程仍应等到并点击「确认上传」，面板随后关闭；**不得**误判「面板已关」而跳过确认、把弹层留在屏幕上 |
| 6.5.16 | 重复点击 | 回填进行中按钮为禁用（显示「回填中…」），重复点击不会发起第二次上传 |
| 6.5.17 | 手动保存前不生效 | 回填完成后**不要**点商品页的保存 → 刷新商品页，新图应当消失。若页面对草稿有自动保存，则以 6.5.5 的「没有 publish / save 请求」为准 |

### 6.5 专项：回填前删第 1 张

> 这些动作发生在 6.5.4「开面板」**之前**。删除是**破坏性且不可撤销**的（本流程不点保存），
> 所以下面每一条都同时检查「删对了」和「没删别的」。

| # | 检查项 | 预期 |
| --- | --- | --- |
| 6.5.18 | 只删一张、删的是第 1 张 | 图片区**恰好少一张**（占用数从 6 变 5 之类）；少掉的是**原来的第 1 张**（商品正面图），其余每一张都还在 |
| 6.5.19 | 重试绝不删第二张 | 若第一次尝试因面板不在本 frame 而换 frame 重试：整个过程**只删过 1 张**。阶段日志里第二次尝试**不应**出现 `DELETE_IMAGE` |
| 6.5.20 | 取消勾选就完全不动图 | 取消「回填前删第 1 张」后回填 → 所有旧图**原样都在**（含第 1 张），新图落在空槽位；若 6 个位全满则报 6.5.7 的错，**不做任何删除** |
| 6.5.21 | 找不到删除图标就停下，不点别的 | 模拟页面改版使删除图标消失 → **红色报错**「…没有找到删除图标，已停止（不会去点别的按钮）。请手动删掉这一张…」，**页面上不产生其它点击**（不得去点商品页任何按钮） |
| 6.5.22 | 点了但图没消失 → 超时并提示确认框 | 出现二次确认框（图仍在）时 → 报 `DELETE_TIMEOUT` 超时并提示**可能弹了二次确认框**；**不得自己去点那个确认**；面板不会被打开 |
| 6.5.23 | 找不到图片区就停，不到处找 | 若 `.imageUploadWrap` 不存在 → 报「页面上没有找到商品图片区…无法确定要删哪一张，已停止」，**不得**到页面别处找同名节点去删 |
| 6.5.24 | 没有旧图时不算错 | 全新商品（一个已占用槽位都没有）勾选删除后回填 → 正常继续，阶段日志写「图片区没有已占用的槽位，无需删除」，**不报错** |
| 6.5.25 | 删图失败时如实告知净损失 | 若删掉第 1 张后上传未确认成功 → 提示必须写明「注意：本次已先删除了原来的第 1 张图（商品正面图），若新图没上传成功需要你手动补回」，**不得**只显示一句失败 |

## 7. 失败与恢复

| # | 检查项 | 预期 |
| --- | --- | --- |
| 7.1 | 单张失败不影响其他 | 在选项页输错密码后重开编辑器 → 全部失败并显示「重试」；恢复登录后点「重试」可成功（其他图片状态不受影响） |
| 7.2 | 失败不阻塞导出 | 存在失败图片时仍可正常导出 PNG |
| 7.3 | 刷新恢复 · 成功项 | 抠图成功后刷新编辑器 → 「已抠素材」仍在，**不会重复提交抠图** |
| 7.4 | 刷新恢复 · 失败项 | 失败图片刷新后仍为失败状态，等待点击「重试」 |
| 7.5 | 刷新恢复 · 进行中 | 上传/处理中刷新 → 复位为排队并自动重新执行 |

| # | 检查项 | 预期 |
| --- | --- | --- |
| 8.1 | 扫描 / 抠图 / 导出不碰页面 | 这三段全程 AliExpress 页面无自动点击、无表单提交、无网络写入到 AliExpress。（**例外**：用户显式点击「回填到商品页」时会操作页面，约束见 8.6 / 8.7） |

| 8.4 | 无远程脚本 | Network 面板中没有加载第三方 JS |

| 8.9 | 无 `web_accessible_resources` | manifest 中确实没有该项 —— 本方案靠 `executeScript` 注入，不需要把文件暴露给页面 |
