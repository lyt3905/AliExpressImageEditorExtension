# AliExpressImageEditorExtension

Chrome Manifest V3 扩展：扫描 AliExpress 卖家后台**商品主图** → 本地下载 → 打开编辑器 → **自动抠图** → 在 800×800 画布上编辑 → 导出**白底 PNG**。

> 第一阶段（MVP）目标：把主流程真正跑通，而不是第一版就做到生产级完善。

---

## 主流程

```text
用户打开 AliExpress 商品编辑页
  → 点击工具栏插件图标（chrome.action.onClicked，无 popup / 无 side panel）
  → 注入/复用 content script → 精确扫描商品图片控件
  → Service Worker 有界并发下载图片
  → 图片 Blob 存入 IndexedDB
  → 创建 Editor Session（chrome.storage.session + IndexedDB）
  → 自动打开扩展内部 Editor Tab（editor/index.html?session=…）
  → Editor 立即显示所有原图（原图不等待抠图）
  → 后台自动对 selected 原图抠图（并发 6，队列调度）
  → 抠图结果自动进入「已抠素材」
  → 默认水印框自动加到图层最上层（锁定，不可编辑）
  → 用户点击素材加入 800×800 画布，拖动 / 缩放 / 旋转 / 镜像 / 排序
  → 需要时「添加文字」：文字是普通可编辑图层（内容 / 字体 / 字号 / 颜色 / 加粗 / 对齐）
  → （可选）右栏「镜像 / 旋转」把选中的那一个图层左转 / 右转 90°、水平 / 垂直镜像，或拖旋钮调任意角度
  → 导出 800×800 白底 PNG（含水印与文字）→ chrome.downloads 下载到本地
  → （可选，用户点按钮）把这张 PNG 作为**一张新图**回填到商品页图片区
```

**不做的事**：不替换商品页已有图片（6 个图片位满时，回填会先删掉**第 1 张**腾出空位 —— 这是全流程唯一
一处删图，见下文「回填到商品页」，可在工具栏关掉）、不点商品页的保存 / 发布 / 提交、不上传商品信息、
不修改服务端。

**唯一会主动操作 AliExpress 页面的功能是「回填到商品页」**，且只在用户点击按钮时发生；它只点素材中心
上传面板内部的「上传图片」与「确认上传」，以及（勾选删除时）商品页第 1 张图上的删除图标，从不点商品级保存。
除此之外全程不碰页面。删图是破坏性操作，所以它在 UI 上默认勾选、可随时关掉，且**只删那一个图标，找不到就停下**，
绝不退化成「点别的按钮试试」。

## 提取范围：只取卖家编辑页的那几张商品图

扫描**精确匹配**卖家后台自己的图片控件，而不是"猜容器"：

```text
.imageUploadWrap
├─ .mainImageSection                                  主图
└─ .moreImagesSection                                 更多图片
     └─ .sell-o-image-item.has-url[data-index="0..4"]   ← 只有这些槽位会被提取
          ├─ .image-item-header-bar > .header-text        → 素材标签（商品正面图 …）
          └─ .sell-o-image-item-preview > .image-card > img   → 原图 URL
```

实测命中这 5 张：商品正面图 / 商品背面图 / 商品实拍图 / 商品侧面图 / 商品细节图，
并写入会话的官方标签（编辑器素材卡片上显示的就是它，不再是笼统的「原图 1/2/3」）。

被**故意排除**的：

| 目标 | 为什么排除 |
| --- | --- |
| 末尾空槽位（`data-index="5"`，无 `has-url`，只有「上传图片」占位） | 里面没有图片 |
| 缩略图上的悬浮预览 `.ait-tooltip` / `.ae-image-hover` 里的同一个 `<img>` | 同一张图的副本，会重复计数 |
| 槽位内的铅笔 / 垃圾桶 / 箭头按钮 | 是 `<svg>`，不是 `<img>` |
| 同一个 `.sell-o-image-item` class 出现在控件**之外**（SKU / 详情图等模块） | 不在上述三个根节点内 |
| `data:` / `blob:` / `.svg` / icon / logo | 页面装饰 |

槽位顺序优先取 `data-index`（全部槽位都有且互不相同时），否则退回 DOM 顺序。

> 兜底顺序（精度不够时才往下走）：控件精确匹配 `seller-widget` → 通用主图容器 `container:*` → 全页商品 CDN `document:product-cdn`。
> 三层都为空才报「未找到商品主图」。

### 加载到 Chrome

1. 打开 `chrome://extensions`
2. 打开右上角 **开发者模式**
3. 点击 **加载已解压的扩展程序**，选择本项目的 **`dist`** 目录
4. 首次使用请打开扩展的 **选项**（`chrome://extensions` → 详情 → 扩展程序选项，或 `dist/options/index.html`），
   填写服务地址 / 账号 / 密码并点击 **登录并保存**
5. 点击工具栏上的插件图标前，先在 `chrome://extensions` 里把本扩展 **固定（Pin）** 到工具栏 ——
   本扩展没有 popup，只能通过工具栏图标触发。

> **必须选 `dist`，不要选项目根目录。**
> `manifest.json` 的源文件在 `public/manifest.json`，只有 `npm run build` 之后才会出现在 `dist/`。
> 如果误选项目根目录，Chrome 会报 **「清单文件丢失或不可读取」**。
>
> Windows 的文件夹选择框需要**先双击进入 `dist`**，再点「选择文件夹」；只在列表里单击选中 `dist` 并不会进入它。

`dist` 目录由 `npm run build` 生成，`manifest.json` / `service-worker.js` / `content-script.js` /
`icons/` / `editor/` / `options/` 都在其中。清单引用的每个文件都可在 `dist` 内解析到
（`dist/icons/icon{16,32,48,128}.png` 由 `python scripts/make-icons.py` 生成，已随仓库提交）。

> 修改 `src/` 后必须重新 `npm run build`，再到 `chrome://extensions` 点击本扩展的 **刷新（⟳）** 按钮才会生效。

### 排错：Chrome 报「无法为脚本加载 JavaScript 'content-script.js'」

这个报错有两种原因，**先看文件在不在**：

```bash
npm run check:dist
```

`npm run build` 现在**自带这一步**：三步构建跑完会校验 `dist/`，缺文件直接以非 0 退出并列出缺了什么。

原因一：**`dist/` 是半成品**。`vite.config.ts` 里 `emptyOutDir: true` 会先清空整个 `dist`，
如果构建在清空之后、写完之前被打断（例如终端被中断），就会出现
`editor/`、`assets/`、`content-script.js` 全部缺失、而 `manifest.json` 还在的诡异状态。
重新跑一次 `npm run build` 即可。

> 在上述开发环境里连续多次执行构建时，整目录清理动作会累计触发沙箱的**批量删除保护**，
> 导致清空到一半失败。规避办法：**一轮里只构建一次**；确需重试时可先把旧目录改名而不是删除
> （`mv dist dist.old`，重命名不走删除钩子）。

原因二：**内容脚本被打包成了 ES module**。内容脚本必须以 IIFE 形式产出（`vite.content.config.ts` 已固定
`format: 'iife'`）。`check:dist` 会用 `new vm.Script()` 把每个内容脚本按**经典脚本**解析一遍，
并拒收顶层 `import`/`export` 或动态 `import()`，因此这类回归会在构建期就被拦下。

### 使用

1. 打开 AliExpress 卖家后台的商品编辑页（URL 含 `product` / `publish` 等）
2. 点击工具栏插件图标
3. 插件自动下载主图并打开编辑器；编辑器打开后**立即**可用，抠图在后台自动进行，完成后自动出现在「已抠素材」
4. 点击素材加入画布 → 拖动 / 缩放 / 旋转 / 镜像 / 图层排序 → **下载 PNG（800×800 白底）**
5. 想用页面外的图？点工具栏「上传图片」选本地文件，或直接 `Ctrl+V` 粘贴截图 —— 会自动抠图并出现在「已抠素材」
6. 想直接把这张图放回商品页？点 **回填到商品页** —— 它会把同一张 PNG 作为**一张新图**放到图片区的空槽位上。
   6 个图片位常是满的，所以工具栏上「回填前删第 1 张」**默认勾选**：回填会先删掉原来的第 1 张（原主图）腾出空位。
   不需要它就在工具栏取消勾选，回填就只追加、不动任何旧图。无论哪种，都不会替你点保存（详见下文「回填到商品页」）
   点下去之后 **最多 10 秒就自动关闭编辑器标签，但回填跑完之前绝不关**（状态条行尾有倒计时和「取消」按钮）。
   回填本身要 5~25 秒、比 10 秒长，这时状态条显示「回填完成后将自动关闭编辑器」，回填一结束就关；
   不想被关就点「取消」。

点击插件后若出错，工具栏图标会显示红色 `!` 徽标，鼠标悬停可看错误原因；最近一次错误也会显示在选项页。

### 排错：悬停提示「当前页面不是 …」「读取不到当前标签页的地址」

点击图标时，插件先用**当前标签页的 URL** 判断这个页面能不能扫描。判断逻辑只有一份，
在 `src/shared/page-gate.ts`（Service Worker、页面适配器、`content_scripts.matches` 共用同一套主机规则）。
被拒绝时徽标显示红色 `!`，悬停提示会带上**实际站点**，Service Worker 控制台还会打印一行
`[AIEE] page gate rejected <原因> <URL>`，对照下表即可定位：

| 悬停提示 | 真实原因 | 处理 |
| --- | --- | --- |
| 读取不到当前标签页的地址 | 浏览器根本没给出 URL | 切到商品编辑页再点一次；仍无效则到 `chrome://extensions` 重载扩展 |
| 当前标签页不是普通网页（`chrome://…`） | 当前页是 `chrome://`、`edge://`、`file://`、`about:` 等 | 新建标签页打开商品编辑页 |
| 当前标签页是插件自己的页面 | 焦点在编辑器/选项页那个标签上 | 切回商品编辑页再点图标 |
| 检测到 AliExpress 的其他地区站点（…） | 当前是 `aliexpress.us` / `.ru` 等地区站点 | 第一版只支持 `aliexpress.com` 卖家后台 |
| 当前页面不是 … 商品编辑页（当前站点：…） | 当前是其他网站 | 同上 |

> 早期版本把以上五种情况都报成「请先在 AliExpress 商品编辑页点击插件图标」，
> 于是「点错标签页」被误读成「页面不支持」，且日志里没有 URL 可查。现已分开报。

## 水印框

可以在选项页配置**多个**水印框，并把其中一个设为**默认**。每次打开编辑器时，默认水印会自动成为
画布上的一个**锁定图层**，永远位于最上层。

**配置**（`chrome://extensions` → 详情 → 扩展程序选项 → 水印框）
- 「添加水印框」选本地图片：PNG（可带透明通道，推荐）/ JPEG / WebP，单张上限 8MB
- 列表里可改名、用单选按钮切换默认、删除（删除会连带清掉本地图片数据）
- **第一个添加的水印自动成为默认**，只用一个水印时无需额外操作

**尺寸**：按「长边铺满 800、居中」等比缩放，绝不拉伸。所以边框类水印请直接做成正方形，
小 logo 想保持小尺寸就先在外部加透明边距做成 800×800（或后续按需扩展为可配置比例）。

**锁定范围**（这是设计上的硬约束，不是靠判断绕开的）

| 能做什么 | 不能做什么 |
| --- | --- |
| 工具栏里整体显示 / 隐藏 | 在画布上点选、拖动、缩放、旋转 |
| 工具栏里临时换成别的水印 | 在图层面板里删除、上移、下移 |
| 参与导出（白底之上） | 被「清空画布」「撤销」影响 |

最后一条是结构保证的：水印**不属于图层文档**（`EditorDocument.layers`），它由 `useWatermark`
单独持有并渲染。因此 `UNDO` / `REDO` / `CLEAR` 在原理上就碰不到它 —— 而不是靠到处加 `if (locked)`。

工具栏的「水印」勾选框与下拉框只影响**本次打开的编辑器**，不会改动选项页里的默认设置；
刷新编辑器会重新回到默认水印。

文件：`src/services/watermark-store.ts`（存储）、`src/editor/state/use-watermark.ts`（注入与锁定）、
`src/editor/components/EditorStage.tsx`（渲染在最上层且 `listening={false}`）。

## 文字图层

工具栏的「添加文字」会在画布中心放一个 `Konva.Text` 图层。它和图片图层共用同一套机制，没有第二套状态：

| 能力 | 实现 |
| --- | --- |
| 数据 | `TextLayer`（`src/shared/types.ts`），纯 JSON —— 不进 IndexedDB、不上传服务端 |
| 增删 / 上移下移 | 复用 `ADD_LAYER` / `DELETE_LAYER` / `MOVE_LAYER` |
| 拖动 / 等比缩放 / 旋转 | 复用同一个 `Transformer`，`scale` 仍是唯一缩放来源（`transformEnd` 后归一化回 1） |
| Undo / Redo | 复用现有 history：**一次编辑只留一条记录** |
| 持久化 | 与图片图层一起写进 `aiee:doc:<sessionId>`，刷新后原样恢复 |
| 导出 | 它就是 Stage 里的真实节点，`toCanvas` 时自然进入 800×800 白底 PNG |

`EditorLayer` 现在是判别联合（`ImageLayer | TextLayer`）：`TextLayer` 没有 `materialId` / `blobId` /
`sourceWidth` / `sourceHeight`，所以 `imageForLayer`（图片加载路径）只认图片，文字永不进入。
水印仍是独立的 `WatermarkLayer`，不进入图层文档，因此**依旧固定盖在所有普通图层（含文字）之上**。

文字属性面板（`src/editor/components/TextPropertiesEditor.tsx`）位于右侧栏、图层列表上方：
文字内容 / 字体 / 字号 / 颜色 / 加粗 / 左中右对齐 / **描边** / **阴影**。
**内容、字号、颜色、描边与阴影的各输入框都在失焦时提交一次**，字体、加粗、对齐与预设按钮是
点击即提交 —— 在输入框里打一行字只会留下 1 条 undo 记录。

### 描边 / 阴影

| 项 | 控件 | 说明 |
| --- | --- | --- |
| 描边 | 颜色 + 宽度 `0–40` | 宽度 **0 = 无描边**；恢复时负值被夹到 0 |
| 阴影 | 颜色 + 模糊 `0–80` + 水平/垂直偏移 `-100–100` + 不透明度 `0–100%` | 模糊和两个偏移**都为 0 时不出阴影** |

- 预设：描边「无 / 白描边 / 黑描边」，阴影「无 / 投影 / 柔和 / 发光」。预设就是一次多字段
  `COMMIT_LAYER`，点一下只占 1 条 undo。
- 两者都在节点自身坐标系里绘制，**跟随图层缩放一起放大**：描边设 4px 的文字放大到 200% 后看起来是 8px。
- 文字描边由 Konva 以字形轮廓为中心绘制，因此开启 `fillAfterStrokeEnabled` 让填充最后画；
  否则一半描边会盖住字身，字看起来比加描边前还细。
- **不影响拖拽手柄**：Konva 的 Transformer 测量被选节点时硬编码 `skipShadow: true`，并遵循我们已开启的
  `ignoreStroke`，所以加描边 / 阴影不会把选框撑大。
- 旧草稿兼容：这两个选项出现之前的文档没有相关字段，恢复时逐字段补默认值（宽度 0 = 关闭），
  老草稿里的文字不会因此被判成损坏。

### 样式记忆

新增的「添加文字」不再是一律 48px 黑字，而是**沿用你上次调好的样式**。

| 记住（12 个字段） | 不记住 |
| --- | --- |
| `fontSize` `fontFamily` `fill` `fontStyle` `align` `stroke` `strokeWidth` `shadow*` | `text`（内容）、`x` `y`（位置）、`width` `rotation` `flipX` `flipY` |

不记内容是因为新图层绝不能带出上一条文案；不记位置 / 旋转 / 镜像是因为每次都应从画布中心、不旋转也不镜像重新开始。

**拖拽缩放不算白做**：用 Transformer 手柄把文字拉大 / 缩小时，松手会把缩放倍数**折算进字号**
（`bakeTextScale`，纯函数 + 单测）。这是唯一一条会让「大小」被记住的路径，理由有两个：

- 右栏「字号」此前会骗人 —— 拖到 3 倍大，框里还写着 48。折算后框里的数字就是你看到的字号。
- 不折算的话新图层只会沿用那个 48。缩放是「变换」（不记），字号是「样式」（记），
  而用户拖手柄时想表达的其实是后者。

折算满足 `fontSize × scale` **严格不变**，所以松手瞬间文字不会跳。字号夹在 12–200，
超出上限的部分继续留在 `scale` 里，以免把文字缩回去；记忆只能带走 200
（800×800 画布上的 200px 字已经占了四分之一高）。落地方式见下方「只在样式补丁上写存储」那条。

- 字段清单是 `src/shared/constants.ts` 里的 `TEXT_STYLE_KEYS`，**单一定义**：`pickTextStyle()`（提交时抽取）、`TextStyleDefaults` 类型、`createTextLayer()` 的入参过滤都从它派生，加字段不会漏。
- 存储在 `chrome.storage.local` 的 `aiee:text-defaults`（`src/services/text-defaults.ts`）。用 `local` 而不是 `session`（关浏览器就该还在），也不用 `sync`（120 次/分钟写配额，样式提交是高频动作）。
- **不进 `EditorDocument`**：文档描述「这张图有什么」，偏好描述「用户习惯」，而且文档在历史栈里，塞进去会污染 undo。加载偏好不 dispatch 任何 action，所以 hydrate 仍然只产生 1 条历史记录。
- 只在样式补丁上写存储：`pickTextStyle()` 对纯位置 / 内容 / 变换的补丁返回 `null`，移动图层和改文案不会触发写盘。文字缩放**会**触发 —— 它折算后带上了 `fontSize`，本来就算一次样式改动；也正因为如此，变换路径不需要任何特例，它和历史栈、属性面板一样都走 `handleCommitLayer`。
- 写入是**整个对象覆盖**而不是 `load → merge → set`：连续两次提交（改完字号立刻改颜色）不会交错读写，天然 last-write-wins。
- 读取和写入都过一遍 `sanitizeTextStyle()`，手工改坏或半截写入的存储项不会把 `fontSize: 99999` 送上画布。
- 存储不可用时静默降级为默认样式，不影响编辑器任何既有行为。
- 面板底部的「恢复默认样式」同时把**当前图层**改回默认（算 1 步撤销）并**清除记住的偏好**，避免误存一套夸张描边后每次新建都带着它。

`x / y` 与图片一样是**几何中心**：`offsetX = width / 2`，`offsetY = 实测高度 / 2`，
因此旋转和缩放都围绕中心发生。文字高度取决于自动换行，首帧用 `estimateTextHeight`
（Konva 默认 `lineHeight = 1`，即 `fontSize × 行数`）估算，节点上屏后由 `EditorStage` 实测校正。

## 镜像 / 旋转（只作用于选中的那一个图层）

右栏图层列表上方会出现「镜像 / 旋转」一栏。**它只变换当前选中的图层**（图片和文字都支持），
没选中任何图层时那里只有一句「选中一个图层后，可对它镜像 / 旋转」。

| 控件 | 行为 |
| --- | --- |
| 旋钮 | 按住拖动即可任意角度旋转，角度读数就在旋钮中央 |
| 旋钮 + Shift | 每 `ROTATE_SNAP_DEG`（15°）吸附一次；不按 Shift 就是自由角度 |
| 双击旋钮 | 归零（本来就在 0° 时不做任何事） |
| 方向键 | 焦点在旋钮上时每按一次 `ROTATE_NUDGE_DEG`（1°），按住 Shift 变成 15°；`Home` 归零 |
| 左转 90° / 右转 90° | 在**当前角度上加** `ROTATE_STEP_DEG`（90°），不是跳到某个固定角度：拖到 30° 后按「右转 90°」得到 120° |
| 水平镜像 / 垂直镜像 | 左右 / 上下翻转，**再点一次还原**；按钮点亮表示该轴当前处于镜像状态 |

- 三个数字都在 `src/shared/constants.ts`（`ROTATE_STEP_DEG` / `ROTATE_SNAP_DEG` / `ROTATE_NUDGE_DEG`）。
- 角度统一归一化到 `[0, 360)`，所以「270° 再右转 90°」是 `0°` 而不是 `360°`。
- 逻辑全是 `src/editor/state/transform.ts` 里的纯函数，各有一条单测：
  `normalizeRotation`（归一化）/ `shortestDelta`（拖动时按最短方向累积角度）/ `snapRotation`（吸附）/
  `transformPatch`（按钮产出哪个补丁）/ `rotationCommit`（旋钮松手要提交什么，或「什么都没变」）/
  `axisScale` 与 `splitSignedScale`（文档的镜像标志 ↔ 节点的带符号缩放）。
- **一次操作 = 一条 undo**：按钮点一下算一步，旋钮**整段拖动**只算一步 —— 拖动期间的角度是直接画在
  Konva 节点上的（`EditorStageHandle.setLayerRotation`），不写状态、不写历史。**不能**走 `UPDATE_LAYER`：
  那会把预览后的文档变成 `history.present`，随后提交时被压进历史栈的正是它，于是撤销会「回到刚才那个角度」，
  表现为撤销没反应。
- 镜像存成 `flipX` / `flipY` 两个布尔字段（`BaseLayer`），**不是负的 `scale`**：Konva 的 Transformer 会把一次
  缩放还原成带符号的 `scale`，负的幅度一旦进了文档就会污染右栏的读数。`transformEnd` 用 `splitSignedScale`
  把节点交回来的带符号缩放拆成「幅度 + 两个镜像标志」，所以**镜像过的图层在缩放后依然是镜像的**。
- 缩放时画布上的选框会跟着角度一起转（Konva 的 Transformer 测量的是节点的绝对变换），这是正常表现。
- 旋转中心仍是图层中心（`x` / `y` 即几何中心），和拖动、缩放一致。
- 旧草稿兼容：这两个字段在「镜像」出现之前的文档里根本不存在，恢复时按 `false` 处理，**老草稿不会被判成损坏**。
- 水印框不受影响：它是锁定图层，永远不会被选中，也就永远拿不到这组按钮。

## 本地图片上传 / 粘贴抠图

除了扫描到的商品图，编辑器还接受两种本地来源，二者走**完全相同**的一条路径：

| 入口 | 操作 |
| --- | --- |
| 工具栏「上传图片」 | 打开文件选择器，可多选。PNG / JPEG / WebP，单张上限 20MB |
| 剪贴板 | 在编辑器任意位置 `Ctrl+V`（例如 `Win + Shift + S` 截图后直接粘） |

粘贴不挑焦点：即使光标正停在文字属性输入框里，只要剪贴板里有图片就按图片处理；剪贴板里
**只有文字时事件原样放行**，往输入框粘文本不受影响。

**上传即自动抠图**：新图以 `selected: true` + `cutoutStatus: 'idle'` 写入会话，随即进入同一个
`CutoutQueue`，所以「抠图进度 x/y」的分母会同步 +1，抠完自动出现在右侧「已抠素材」里。
上传的图**不会**自动落到画布上 —— 由你在素材面板里点选，和商品图完全一致。

- 校验是**逐张**的：单张过大 / 非图片 / 尺寸解析失败只跳过那一张，同一批里其余照常加入，
  顶部提示条会说明跳过了哪些、为什么。
- 校验顺序：空文件 → 超过 20MB → mime（先信声明类型，不在白名单就嗅探前 16 字节）→ 尺寸。
  截图粘贴常常没有 `type`，靠的正是这一步嗅探。
- `src/services/upload-images.ts` 干的是「写 blob + 追加 `SessionImage` + `putSession`」，
  **不是**纯内存操作。
- 素材 id / blobId 统一用 `upload-` 前缀；扫描图的 id 是 URL 哈希，两者结构上不可能撞。
- 粘贴来的无文件名截图会补成 `本地图片-1.png` 这样的标签，否则素材卡片会是一行空标题。
- 与下载链路共用 `src/shared/image-mime.ts` 的同一套 mime 判定（`background/` 是 SW 专属，
  编辑器不能 import，所以放在 `shared/`）。

> **为什么必须落盘**：`use-editor-session` 每次加载都是先按会话记录重建素材列表，再用
> `keepLayerWithMaterials()` 过滤草稿图层。上传的图如果只活在编辑器内存里，刷新之后素材没了，
> 引用它的图层就会被当成垃圾一并滤掉 —— **画布上那张图凭空消失**。

## 回填到商品页（往图片区放一张新图）

编辑器工具栏的 **回填到商品页**：把刚合成的 800×800 白底 PNG 送回商品页图片区。

**默认先删掉第 1 张，再放新图。** 6 个图片位常是满的，而速卖通只在**空槽位**上渲染上传入口
（`div.upload-content`，旧版页面包在 `div.image-upload-btn` 里）——
没有空位就无处可放。所以工具栏上有一个默认勾选的 **回填前删第 1 张**，回填时先删掉原来的第 1 张
（原主图）腾出空位。取消勾选后回填就只追加、不动任何旧图。

位置要提前说清楚：速卖通删掉第 1 张后，**后面的图会自动前移**，所以空出来的是**最后一个**槽位 ——
**新图会落在最末尾，不会自动成为第 1 张**。想让某张图当主图，删完之后在商品页里手动拖一次。
上传面板绑定在「从哪个槽位的入口打开」上：流程只点**最后一个空槽位**的入口，确认上传后新图就追加到末尾；
**绝不会**从已占用槽位的入口开面板 —— 那会让「确认上传」覆盖那张旧图（真机踩过）。

流程（`src/background/page-filler.ts` → 注入 `public/vendor/aeiir/`）：

1. 编辑器用**和「下载 PNG」完全同一次**的合成结果，先比 5MB 上限，再发给后台。
   （尺寸检查在删图**之前** —— 超限的 PNG 绝不会让你先损失一张旧图。）
2. 后台在**每个 frame** 里跑一次只读探测，挑出持有商品表单的那个 frame（每个结果自带 `frameId`，
   所以不需要 `webNavigation` 权限，也不需要 `all_frames: true`）。
3. 注入经典脚本。勾选了删除时，**先删旧图**（删除图标就在商品页上，不需要面板；先删再选槽位才选得准，
   因为删除会让图片区重排）→ 点上传按钮开面板 → 定位拖拽区 / 文件输入框 → 注入文件 → 等上传信号 → 点「确认上传」。
   面板**已经开着**时直接复用、不再点按钮 —— 跨 frame 重试时再点一次会把面板关掉；你按提示手动打开过也一样。
4. 面板如果不在这个 frame 里，桥回报 `UPLOAD_PANEL_NOT_FOUND`，后台**换 frame 重试**（最多 3 次）。
   **重试绝不删第二张**：第一次尝试已经删过第 1 张了，再删一次就轮到第 2 张，所以 `removeFirstImage`
   只在 `attempt === 1` 时为真。

细节：

- **红线**：只点上传面板内部的「上传图片」与「确认上传」，以及（勾选删除时）第 1 张图上的删除图标，
  **绝不**点商品页的保存 / 发布 / 提交。最后保存与否始终由你决定。
- **删图失败就停，绝不猜**：找不到删除图标 → 直接报「在第 1 张图（商品正面图）里没有找到删除图标，已停止
  （不会去点别的按钮）」，**页面上不产生其它点击**；点了但它没消失（例如弹了二次确认框）→ 报
  `DELETE_TIMEOUT` 并提示可能有确认框，**不会自己去点那个确认**；图片区整个找不到 → 报
  `IMAGE_AREA_NOT_FOUND`，**不会到页面别处去找同名节点删**。
- **删掉的图只能手动补回**：删图不可撤销（本流程不点保存）。万一后续上传没确认成功，提示会明确写出
  「注意：本次已先删除了原来的第 1 张图（商品正面图），若新图没上传成功需要你手动补回」——
  不会让你以为一切正常。
- **图片位满了会明确报错，不会瞎点**：真实页面**只在空槽位上**渲染上传入口
  （`div.upload-content` / `div.image-upload-btn`），所以 6 个槽位全满时页面上一个入口都没有。
  这时报「商品页的图片位已经全部占用（6 个槽位都有图），…请先删掉一张、腾出空位再回填」，
  **页面上不产生任何点击**。（勾选删除时通常走不到这里：删完第 1 张就有空位了。）
- **空槽位的入口找不到也报错，绝不覆盖**：有空槽位但入口（改版后）找不到时，报
  「图片区还有空槽位，但没有找到可点击的上传入口…请先手动打开上传面板」。没有空槽位入口时
  **直接拒绝**，不存在「退化到已占用槽位的按钮」—— 那种点击会覆盖旧图（真机踩过，已删除该路径）。
- **未确认会如实说**：如果面板没关、或没有「确认上传」按钮，提示为「回填未确认：…」而非成功。
- **会等到图片真的传完再点「确认上传」**：缩略图是本地渲染的，它一出现并不代表已经传完；传完之前
  「确认上传」是灰的。所以这一步最多等 25 秒，上传中一直等、不做任何兜底点击（兜底会点中页面里
  另一个弹层的按钮）。面板真的关掉会立即结束，不会白等。
- **商品页已关闭 / 会话过期**：分别提示「原来的商品页标签已经关闭…」「会话已过期…」，页面上不产生任何点击。
- **回填跑完最多 10 秒后自动关闭编辑器标签**：10 秒是**下限**，从**点击那一刻**开始算；但回填结束之前**绝不关**
  —— 回填要 5~25 秒，而且在后台 Service Worker 里跑，关掉编辑器会断掉那条消息端口，而回填正处在「已经删掉第 1 张、
  新图还没传完」的中间态。所以慢的时候状态条显示「回填完成后将自动关闭编辑器」，回填一结束立即关；快的时候
  （回填 3 秒就结束）仍等到第 10 秒才关，不会一闪而过。无论回填成功、未确认还是失败都会关（结果同时写在扩展图标的
  悬停提示上，所以关掉页面不会丢信息）。**点「取消」可以留下编辑器**。
  关标签是编辑器自己 `window.close()`；万一被浏览器忽略，会再请后台按会话 id 精确关闭该标签 ——
  **只关这一场会话的编辑器页，绝不碰商品页**。
- 复用姊妹扩展 `aliexpress-image-replace-test-extension` v0.5.1 的 6 个库文件（原样 vendor 到
  `public/vendor/aeiir/`，**未移植成 TS**），加一个本项目的 `bridge.js` 作为页面侧驱动。
  原因与踩坑见 [`docs/architecture.md`](docs/architecture.md) §6.5。

> **为什么不用 `web_accessible_resources`**：本方案靠 `chrome.scripting.executeScript({ files })` 注入，
> 不需要把脚本暴露给页面（已实测确认）。

手工验证步骤见 [`docs/manual-test.md`](docs/manual-test.md) 第 6.5 节。

## 成品图工坊（本地合成，未接任何 AI 服务）

工具栏「成品图工坊」把一张**已抠素材**做成一张成品展示图（1000×1000 PNG）。

**核心约束：商品像素零重绘。** 背景、台面、倒影、接触阴影、边缘光、暗角全部由参数画出来，
商品本体是抠图 PNG 原样绘制。这样成品不可能与实物有出入 —— 对跨境潮玩来说，
「看起来像另一款」比「不好看」贵得多。

### 六套模板

| 模板 | 可否做首图 | 特点 |
| --- | --- | --- |
| 纯白影棚 | 是 | 速卖通首图合规，产品占比 78% |
| 浅灰渐变 | 是 | 比纯白有质感，仍是浅色纯底 |
| 深色聚光 | 否 | 潮玩感最强，适合第 2–6 张 |
| 工业车间 | 否 | 金属冷调 + 暖色边缘光，机甲题材 |
| 收藏柜 | 否 | 暖光木色 |
| 赛博街区 | 否 | 霓虹紫蓝，风格最重 |

模板是**参数**（渐变角度、地面线、阴影椭圆、边缘光颜色、暗角强度），不是图片资源：
任意输出尺寸都清晰、六张图风格统一、可复现、零体积。

### 合成链路

```text
抠图 Blob
  → 解码（createImageBitmap，2s 超时则退回 <img>，避免解码卡死时界面永远停在「合成中」）
  → 边缘净化（颜色去污 + alpha 对比 + 1px 收边）
  → 裁掉透明留白（alpha 包围盒）
  → 布局：最长边 = 画布 × 占比，居中并上移一点给阴影留位置
  → 画背景 → 台面 → 倒影 → 接触阴影 → 边缘光 → 商品 → 暗角
  → 1000×1000 PNG
```

### 两个必须说的细节

1. **边缘净化解决的是两种不同的毛病，缺一不可。**
   - *颜色污染*：抠图输出的边缘像素是「商品色 × α + 白底 × (1-α)」的混合，在白底上看不出来，
     贴到深色背景上就变成一圈白边。用反混合公式还原真实颜色。
   - *多余的 alpha*：剪裁蒙版比物体本身大一圈时，外圈是一圈半透明白色。这些像素**本来就是白的**，
     反混合只会还原出白色，救不了。只能靠 alpha 腐蚀（min 滤波）把这圈收掉。

   只做前者，深色模板上的白圈基本不会改善 —— 这是渲染出来对比才发现的。

2. **布局必须按 alpha 包围盒算，不能按图片尺寸算。**
   抠图 PNG 四周常有透明留白，按图片尺寸布局会让投影落在留白边缘而不是商品底部，
   成品看起来是「悬浮的」。裁剪在合成前完成，不是可选优化。

### 已知边界

- 只产出图片，不自动加文字 / 水印：速卖通对主图文字敏感，这一版不冒这个险。
- 不自动回填：成品是 1000×1000，而回填链路按 800×800 校验；接回填时要单独处理尺寸与 5 MB 上限。
- 首图位目前**改不了**：现有回填只能追加到末尾空槽（详见 §6.5 的说明），换掉第 1 张需要拖拽排序能力。
- AI 识别 / AI 生成背景尚未接入：模板里的 `promptFragment` 已经为将来的文生图供应商留好了位置。

## 版本号规则（每次改动都要递增）

**每次改动都必须递增版本号**，否则装扩展时无法确认跑的是新包还是旧包——
改了代码没生效，第一嫌疑永远是"没重新加载"，而版本号是唯一能一眼确认的证据。

```bash
npm run release     # 递增 patch + 构建（推荐的日常流程）
npm run bump        # 只递增，不构建
npm run bump -- minor   # 0.7.x → 0.8.0
npm run bump -- major   # 0.x → 1.0.0
```

`scripts/bump-version.mjs` 同时写 `package.json` 和 `public/manifest.json`，并在两者不一致时**报错退出**——
Chrome 只读 manifest，只改一处会产出一个"看起来已发布、实际还是旧号"的包。

面板标题旁显示的就是 `chrome.runtime.getManifest().version`，和扩展管理页一致。

## 大头照主图（信息型主图，800×800）

工具栏「大头照主图」：把一张抠图做成店铺在用的那种**信息型主图** —— 包装图 + 大头照 + 型号大字
+ 发货徽章 + 店铺条。

**蓝色外框不由本扩展绘制，也不为它预留边距。** 那是店铺的固定模板，后期直接盖在成品图上；
所以版式按满幅铺排，贴边就贴边。

和上面的「成品图工坊」是两件事：工坊卖「这东西长什么样」（氛围），主图卖「这是什么、多久发货」
（信息）。两者共用抠图预处理（边缘净化 + 留白裁剪），版式各写各的。

### 版式

| 区块 | 位置 | 说明 |
| --- | --- | --- |
| 包装图 | 左上 | 可选，白色底板 + contain，不拉伸；唯一保留内距的区块 |
| 大头照 | 右中 | 取商品顶部 42% 作取景，向右下出血 |
| 型号大字 | 右上 | 右对齐，字号按可用宽度自动收缩 |
| 发货徽章 | 左下 | 两行文案都可改，同样按宽度二次收缩 |
| 店铺条 | 右下 | 蓝底白字，一直延伸到右边缘；与徽章之间留一道细缝 |

**「大头照」不是把整张图放大**，而是取商品顶部的一段作取景、再让它超出画布右下边缘。
放大整张图会连脚一起放进来，得到的是一张「更大的全身照」；裁切 + 出血才有推近镜头的压迫感。

### 可调参数

`headRatio`（取景高度，越小越「大头」）、`headZoom`（放大）、`headOffsetX`（左右）、
`headRotation`（倾斜，默认 −6°）、四个勾选项（包装图 / 徽章 / 店铺条 / 去白边）。
文案四个字段全部可改，改完点「生成预览」。

### 为什么输出 800×800

和编辑器、回填链路保持一致：回填按 800×800 组织，尺寸不同要另写一套校验。
1000×1000 也在支持范围内（`clampPosterSize` 允许 800–2000），但要走回填就得先改那条链路。

### 已知边界

- 只有一个版式。参考图里的**透视**（包装图斜放、商品带角度）没做，只做了平面旋转。
- 字体用本机 `Arial Black`，不内嵌商用字体（版权 + 体积）。
- 右下角的店铺 logo 位还没做。
- 有文字和边框的主图在速卖通属于**信息图**，首图位有「无边框 / 无文字」的规范；
  实际审核较宽松，但这是产品决策，不是代码能替主人决定的。

## 三图叠放（新主流程）

现在的目标版式是：**三张不同角色的商品图叠在一起，最后盖上固定水印**。

```text
原始素材（扫描到的全部主图）
  → 全部抠图
  → AI 分类：每张判定「人形 / 变形形态 / 包装盒 / 配件 / 其他」
  → 每类选一张（缺的那类由其余图里次优的一张顶上）
  → 三格叠放：盒子（最后、最小）→ 变形图（中）→ 主图头胸特写（最前、最大）
  → 盖上 800×800 固定水印 PNG
```

工具栏「主图生成」把这条链路串起来：一次分类（并发 3，约 3–6 秒），三格自动填好，
每格都可以手动换。**没配识图服务也能用** —— 手动给每张图选角色即可。

### 选图规则（`services/stack/pick.ts`）

两趟，顺序不能反：

1. **先放本职角色**：`figure` → 主图、`alt` → 中间、`box` → 后面。各取本角色里分数最高的一张。
2. **再补空缺**：只有本职角色都放完了，剩下的图才会被提拔去填空。

第一趟必须先跑。否则「只有人形 + 盒子」的商品，按 hero → second → third 顺序填，会把盒子塞进
中间那个大格，看起来像第二个主图。先放本职，「盒子」就落在它该去的小角落，中间留空由版式处理。

分数 = `置信度 × 0.55 + 主体占比 × 0.45`：模型对**角色**的把握比画面占比更有信息量，
一张细节特写可能占比很高但根本不该当主图。

### 送到画布编辑：三个独立图层

面板底部「送到画布编辑」把三张抠图**作为三个独立图层**放回主画布，位置用量的是预览那套布局，
所以落点和预览一致。之后就是编辑器已有的能力：拖动、缩放、旋转、调层序、撤销。

**水印不烧进图里**：编辑器有锁定的水印框，导出时叠一次。面板再叠一次就是两个水印。

一个已知差异：「取景」模式下预览显示的是截取的区域，而图层只能是整张图——那种模式下送到画布
会看到完整素材，需要你在画布上自己调。默认的「整图放大」模式和预览完全一致。

### 性能：一次调用分类全部图片

6 张图逐张分类是 6 次调用，并发 3 也要两轮，**约 8 秒纯等待**。

现在拼成一张 **3×2 联络图，一次调用返回 6 条结果**，8 秒变 4 秒左右。
模型漏掉某几格时，只对漏掉的那几张补调（不是整批重来）。

同时**默认不再调用「构图建议」**：它只输出"大/中/小"，而大小已经能拖滑杆控制，
4–15 秒的成本换不来东西。按钮还在，需要时手动点。

批量 20 个商品，从约 15 分钟降到 7 分钟上下。**抠图那 10–20 秒省不掉**，是服务端成本。

### 全自动：一次点击出图

抠图全部完成后，**主图面板自动打开，并自己跑完四步**：

```text
① 分类（并发 3） → ② 构图建议（联络图一次调用） → ③ 合成 → ④ 保存到下载目录
```

面板顶部实时显示进行到哪一步。**任何一步失败都会停下来并保留手动按钮**，
自动路径不会是死胡同：

| 失败点 | 表现 |
| --- | --- |
| 识图服务没配 | 提示"请手动选角色"，三格下拉照常可用 |
| 分类失败 | 对应卡片标红写原因，其余照常 |
| 构图建议失败 | 退回默认构图，继续往下跑 |
| 合成失败 | 停在第 ③ 步，可点「生成预览」重试 |

「重跑全流程」按钮可以再走一遍（分类有缓存，第二次几乎瞬时）。

**切换构图强度会立刻重排**，不用再点生成；选择会记在本机，下次打开沿用上次那档。

### 主图宽度上限 50%

只按高度定尺寸是不够的。素材如果**旁边印着小图**（头部三视图、第二视角），
按高度缩放会把宽度撑到画布的 70%，从左侧一路盖住盒子和摩托——三张糊成一团。

所以主图多一条**宽度硬上限**（50% 画布，档位会小幅调整）。超了按宽度回缩，
保持比例：变成一列窄一点，而不是裁掉一部分。

### 默认版式：固定分格

最终采用的版式（`DEFAULT_STACK_SLOTS`）来自一次渲染样张，卖家确认"就按这个"：

| 槽位 | 框（画布比例） | 裁切 | 倾斜 |
| --- | --- | --- | --- |
| 包装盒 | 0.06, 0.05, 0.35 × 0.36 | 完整 | 0° |
| 变形形态 | 0.00, 0.29, 0.55 × 0.46 | 完整 | 0° |
| 主图 | 0.31, 0.08, 0.76 × 1.20 | **整图**，放大到 1.2 倍画布高 | 0° |

三个槽位都不倾斜 —— 倾斜是早期为了让"叠放"看起来不那么僵硬，但实际效果像贴歪了的贴纸。

位置写死，`构图强度`（三档）和 AI 的 `scale` 只做**整体缩放**，围绕各自的锚点（主图右上、
变形左下、盒子左上），所以放大时不会跑偏。

按图自适应的 `planAutoStack` 保留在 `auto-layout.ts` 作为备选，默认不启用。

### 位置固定，AI 只管大小

**主图永远在右，变形形态和包装盒永远在左。** 模型给的 `anchor` 被忽略。

原因很直接：模型对"放左还是放右"每跑一次都可能改主意（"主体宽 → 居左" / 下次又"居右"），
同一款商品拍两次会出两张不一样的图。**波动不是灵活，是漂移。**

尺寸仍然自适应：模型和自检可以缩小挤到别人的那张、放大太小的那张。

### 三条防呆规则

这三条都是被实际成品打回来才加的：

| 规则 | 起因 |
| --- | --- |
| **主图不倾斜、顶部 y=0** | 曾经是 −3° + 顶部出血 8px，两个叠加把头推出画布，成品只剩一个胸 |
| **盒子左边只出 8px** | 曾经出 26px，把盒子上的 "TRANSFORMERS" 切掉半个 S |
| **三张不能同侧** | 模型可以连说两次"往右移"，结果三张全堆右边，左边空掉三分之一 |

`balanceAnchors()` 只在"三者全同侧"时介入，把两张辅助图拉回左侧；刻意安排的布局不会被推翻。

### 「主图只保留主体」开关（默认关）

素材带小图时，打开它：找出 alpha 上最大的一块连通区域，其余置为透明。
不重绘、不修边、不去倒影，只回答「哪一块是商品」。

默认关，因为主人要求"只用抠图 API"。但**带三视图的那类素材必须开**，
否则版式一定乱——那不是布局算法能解决的，算法没法知道右边那三块不是商品。

### 合成后 AI 自检（默认开）

这是唯一让模型**看到成品**的环节。之前它只能看三张并排的联络图，不知道叠起来什么样——等于盲拍。

```text
合成 → 把成品图发给模型 → 它只报问题 → 引擎按规则调一次 → 重新合成
```

模型可以给两层信息，**都可以没有**：

**① 问题**（`issues`）——它看见了什么

| 它说 | 引擎怎么做 |
| --- | --- |
| 某张被盖住（`covered`） | 缩小**压在前面的**那一张，不是缩小被盖的 |
| 某张被裁太多（`cropped`） | 缩小那一张 |
| 整张挤（`crowded`） | 三张各降一档 |
| 太空（`empty`） | 主图升一档 |

**② 修改动作**（`fixes`）——它想怎么改，优先采用

```json
{"fixes":[{"slot":"second","action":"shrink"},
          {"slot":"third","action":"grow"}]}
```

动作只有五种：`shrink` / `grow` / `move-left` / `move-center` / `move-right`。
全是已有维度的枚举，**没有坐标**——它测不出坐标，给了就是编的。

只给问题、不给动作时，引擎按上面的规则自动修。两种路径都是每个槽位每轮最多动一档。

**关键细节**：自检时会附上「当前构图：主图靠右、变形形态靠左…」，否则模型会建议
「变形形态左移」——而它已经在最左，提了个正确但无用的意见。

代价：多一次视觉调用（约 4 秒）。可在面板里关掉。「自检失败不丢图」：出错就保留当前构图继续保存。

### 抠图结果原样使用，不做二次处理

主图流程只调用抠图 API，**拿到什么就用什么**：

- 不修边缘（白底上白边不可见，修它只会啃掉细节）
- 不做连通域裁剪、不去倒影、不换背景

理由很简单：多一道处理就多一处和抠图服务打架的地方，出问题时也不知道该找谁。
素材本身的问题（比如参考图右侧带一张小图）应该在素材或服务侧解决。

唯一的"处理"是按 alpha 包围盒裁掉**透明留白**——那不是改像素，是算布局尺寸，
否则阴影和位置都会按图片外框算，而不是按内容算。

### 构图：整张素材摆上去，由画布边缘来裁

**素材永远不预裁切。** 产品图按原样整张缩放、整张绘制，超出 800×800 的部分被画布边缘切掉 ——
和海报被画框裁掉是同一种裁切，而不是"先把人裁成半身再放上去"。

早期版本取「顶部 40%」当"大头照"，渲出来是"一个胸"，不是"一支擎天柱"。买家要判断的商品
已经不在画面里了。**"出血"和"裁素材"不是一回事**，混在一起就做错了。

| 槽位 | 尺寸 | 位置 | 出画 |
| --- | --- | --- | --- |
| 主图 | 整图，高 = 画布 × 1.4 | 右侧，顶部对齐 | 腿出下边（**缩放导致，不是裁切**） |
| 变形形态 | 宽 = 画布 × 56% | 左下，底对齐水印线 | 下沿略微压线 |
| 包装盒 | 高 = 画布 × 56% | 左上，斜置 9° | 左边只出 8px（品牌名在边上） |

三档构图强度只改**尺寸系数**，不改"完整还是裁切"：

| 档位 | 主图 | 变形形态 | 包装盒 |
| --- | --- | --- | --- |
| 主图优先 | ×1.08 | ×0.86 | ×0.86 |
| 均衡（默认） | ×1.00 | ×1.00 | ×1.00 |
| 细节优先 | ×0.92 | ×1.16 | ×1.20 |

### AI 出意图，几何出像素

模型**不返回坐标**，只回答「靠哪边」（`anchor`）。尺寸由档位统一决定 —— 整图布局里，
"多大"是全局比例，让模型逐张判断反而会把三张的关系搞乱。

### 主图：整图放大，不裁切

主图是**整张照片按 1.4 倍画布高缩放**后放上去的，超出画布的部分被边缘切掉。
不是"先把图裁出头部那块再放大"。

区别很重要：

| | 裁切素材 | 缩放后出画 |
| --- | --- | --- |
| 丢像素 | 是的，下半身永远回不来 | 不丢，只是位置超了 |
| 调小一点 | 只能看到框内的 | 腿会从画布外回来 |

「主图高度」滑杆（50%–200% 画布）控制这个倍数：100% 是整只刚好放下，120% 是常规，
180% 接近头肩。改动即时重排。

**这里没有宽度上限。** 曾经有过，但它会悄悄废掉滑杆：方图放大超过约 1.2 倍后宽度必超限，
被压回同一个值，滑杆看起来像坏的。现在大小完全由滑杆决定，拖大了盖住辅助图就拖回来。

### 水印：直接用设置页那一张

主图合成时从设置页读**默认水印框**原样叠加。没标记默认时取上传的第一张——
「我明明设了水印却没出来」比「用错了一张」更糟。

### 型号文字：只抄看得见的

分类时顺带读图上印的编号（`BT-01`、`FT-32C`），读到就画在主图右上角，黑色粗体。
**读不到就空着，不猜、不补全** —— 线上商品的型号写错就是退货单。

面板有「型号文字」输入框，识别错了可以直接改，改完立即重排。字号随字符串长度自适应，
最长不超过画布宽度的 46%。

### 主图优先选「现成的特写」

店铺现成的模板（BT-01 那类）用的是一张**已经拍成半身特写的图**，不是把全身照放大裁出来的。
所以分类多了一个维度：

| `framing` | 含义 | 用途 |
| --- | --- | --- |
| `closeup` | 头顶到腰，主体占满画面 | **主图优先**（+0.25 分） |
| `full` | 全身/整车都在画面内 | 辅助槽位优先（+0.08），主图扣分 |
| `none` | 盒子、配件、看不清 | 不加不减 |

权重给得很重（0.25），因为它决定「能不能像模板」——同一支人形两张图的置信度差异只是噪音。

面板卡片会标出「特写 / 全身」，方便确认分类有没有认对。

### 主图不要「拼图」

多角度拼图（人形和载具并排在同一张图里）如果被选为主图，会**占满整个画面**，
另外两张就没位置了——成品看起来只有一张图。

两道防线：

1. **分类**：一张图里出现两种形态 → 必须判 `other`，不进主图候选
2. **选图**：主图的候选按`竖构图`加分。单个人形照是竖的（宽/高 < 0.85），拼图是横的（> 1.25）。
   横图扣 0.12 分，竖图加 0.12 分

第 2 条是几何信号，比让模型判断"这是不是拼图"可靠——模型的判断会漂，宽高比不会。

### 分类是封闭选择题

提示词只允许五个答案（figure / alt / box / accessory / other），不是开放式描述 ——
开放式描述每次返回都不一样，版式没法被一段散文驱动。模型给出未知 role 时降级为 `other`，
不抛错：那是措辞失误，不是丢掉一张图的理由。

### 版式由水印倒推出来

`水印.png` 实测：800×800 RGBA，**84% 像素透明**，蓝框约 10px，**y ≥ 682 的整条底部**
被蓝色店铺条 + 黄色徽章占住。所以真正能放商品的空间是 **约 780 × 665**。

主图允许越过这条线、被徽章压住一角（卖家确认过），两张辅助图留在可用区内。

| 槽位 | 裁切 | 位置（**固定**） | 作用 |
| --- | --- | --- | --- |
| `hero` | 整张 | 右侧，脚下出血 | 视觉主体 |
| `second` | 完整（contain） | 左中，被主图压住右端 | 变形形态 |
| `third` | 完整（contain） | 左上，最小 | 包装盒 |

三个 `box` 全部是画布比例（`.06/.05/.35/.36` 这种），改数字就能挪位置，不用碰渲染代码。
层与层之间**故意重叠**：不重叠就不是"叠放"，而是"拼贴"。

### 两套版式并存

- **三图叠放**（`services/stack/`）：新主流程，叠加用户水印 PNG
- **单图版式**（`services/poster/`）：旧的单图 + 代码画的框，保留但不再是主线

共用 `showcase/prepare.ts`（边缘净化 + alpha 裁剪），因为这两个 bug 只该修一次。

### 水印从哪来

直接复用现有的「水印框」配置：设置页上传一次 800×800 PNG，主图合成时读默认水印的 blob
叠加。不需要新开一个上传入口，也不会写进代码仓库。

## 识图服务（本地网关 · 只用来读型号）

设置页可以配置一个**本地** OpenAI 兼容网关，主图面板里的「AI 读型号」按钮会用它从包装盒/产品图上
读出型号，自动填进输入框。

- 默认 `http://127.0.0.1:8788/v1`，模型 `glm-5v-turbo`
- 密钥以 `Authorization: Bearer` 发送，**只存在本机扩展存储**（`chrome.storage.local`），
  不进仓库、不进 URL、不打印日志
- 服务没启动不影响任何其他功能，按钮只会报错

### 为什么只做「读型号」

这台网关上 14 个模型**全部是 `text+image → text`，没有一个能出图**。所以 AI 在这里只能做两件事：
看懂图、说出结构化事实。而「读懂图再重绘商品」恰恰是最危险的用法——模型会改商品细节，
变成「描述不符」。

真正省事、又不承担风险的那一件是 OCR 级的：**把包装盒上的型号读出来**。写错型号是实打实的纠纷，
而读型号是可核对、可回退的。

| 模型 | 耗时 | 型号 | credit |
| --- | --- | --- | --- |
| `glm-5v-turbo`（默认） | 2.3s | FT-32C ✓ | 0.14 |
| `hy3` | 2.1s | FT-32C ✓ | 0 |
| `deepseek-v4.1-flash` | 3.8s | FT-32C ✓ | 0.06 |
| `kimi-k3-1` | 6.2s | FT-32C ✓ | 0.78 |

四者都能读对；默认选 `glm-5v-turbo` 是因为输出最短、最稳定（31 completion tokens）。
想要零成本可以换成 `hy3`。

### 解析要能扛住模型的花样

`services/vision/prompt.ts` 里两个纯函数：

- `extractJsonObject()` 用**花括号配对**（不是正则）从 ```json 围栏或前后夹着解释文字的回复里
  抠出 JSON。正则要么被字符串里的 `}` 骗停，要么贪婪吞掉多余内容。
- `parseVisionTags()` 把字段归一化：`model_code` / `modelCode` 两种写法都认，
  型号统一大写，`palette` 去重截断到三个，`confidence` 兼容 `0.95` / `95` / `"90%"`。
  全空才返回 `null`；**只读到型号、没读到品类**的半个结果照样可用。

21 条单测覆盖了围栏、前后缀、字符串内花括号、嵌套对象、截断响应、百分比置信度等情形。

## 服务端接口（**只调用已有接口，服务端未做任何修改**）

服务地址：`https://39.107.244.239`（可在选项页修改默认值）

| 用途 | Method + Endpoint | 请求 | 响应 |
| --- | --- | --- | --- |
| 登录 | `POST /api/auth/login` | JSON `{username, password}` | `Set-Cookie: SESSION=…`；`{success,data:{id,username,role,…}}` |
| 登录态 | `GET /api/auth/me` | Cookie | `200` + `{success,data:{…}}`，未登录返回 `401` |
| 退出 | `POST /api/auth/logout` | Cookie | `{success:true}` |
| 上传图片 | `POST /api/admin/uploads/images` | `multipart/form-data`，字段名 **`file`** | `{success:true,data:{url:"https://…aliyuncs.com/….png"}}` |
| 抠图 | `POST /api/public/toy-image/v1/background/remove` | JSON `{input_url, max_size:1600}` | **平铺** `{job:{…},asset:{id,kind,url}}` |
| 取结果 | `GET asset.url` | — | `image/png` 字节流 |

### ⚠️ 响应结构不一致（已踩坑，务必注意）

该服务端**两族接口的响应包装方式不同**：

| 接口族 | 结构 |
| --- | --- |
| `/api/auth/*`、`/api/admin/uploads/images` | `{"success":true,"data":{…}}`（信封） |
| `/api/public/toy-image/v1/background/remove` | `{"job":{…},"asset":{…}}`（**平铺，无 `data` 字段**） |

早期版本按信封读取 `data.asset.url`，于是**每次抠图都会失败**并报
`抠图响应缺少结果图片地址` —— 尽管服务端其实已正确返回了结果 URL。

`readRemoveBackgroundPayload()` 现在两种结构都接受，并把错误消息一并透出
（服务端失败时返回的是平铺 `{"error":"internal_error","message":"…"}`，同样**没有 `success` 字段**）。

已加入**线上契约测试**用于持续防回归（默认跳过，不联网）：

```bash
AIEE_LIVE=1 AIEE_USERNAME=admin AIEE_PASSWORD=<密码> npm run test:live
```

> 单元测试只能断言「我以为的结构」，所以这个 bug 能通过全部 87 个单测。
> 只有真实调用线上接口的测试才能发现它。

**鉴权方式：仅 Cookie（`SESSION`）**。服务端没有 header/token 方案（`X-Session-Id`、`Authorization` 等均实测返回 `401`），
因此扩展依赖 `credentials: 'include'`：

- 扩展在 `manifest.json` 中声明了 `https://39.107.244.239/*` 的 `host_permissions`；
  按 Chromium 的 SameSite 规则，**扩展对该域的请求被视为 same-site**，`SameSite=Lax` 的 SESSION Cookie 因此会被正常携带。
- 密码**不落盘**：只写入 `chrome.storage.session`（内存级，浏览器关闭即失效），用于登录过期后的自动重登。
- 用户名与服务地址写入 `chrome.storage.local`。
- 代码不打印任何凭据，Cookie/密码不会出现在 URL、日志或构建产物中。

**为什么不是「服务端抓取外部图片」**：扩展先把图片下载成 Blob，再用 `multipart` 上传给服务端；
服务端从**它自己的对象存储**读取该 URL 做抠图。AliExpress 的外部 URL 从未交给服务端。

### 关键取舍（真实限制）

- 服务端**不支持**直接 `multipart` 上传到抠图接口（实测字段 `file`/`image`/`source` 均返回
  `{"error":"bad_request","message":"Missing field: input_url"}`），所以必须先上传拿 URL，再调抠图接口。
- 服务端存在 `POST /v1/background/remove-inline`（原始字节进 / PNG 字节出，最契合本用例），但：
  - 公开前缀 `/api/public/toy-image/v1/background/remove-inline` → `404`
  - 鉴权前缀 `/api/toy-image/v1/background/remove-inline` → `403 Forbidden`
  即对当前账号不可用，因此项目走「上传 + `input_url`」这条可用链路。
- 抠图结果落在服务端对象存储上（`*.aliyuncs.com`），扩展会立即 `fetch` 回 Blob 存进 IndexedDB，
  编辑过程只用本地 Blob，**不持续依赖远程文件**。因此 `host_permissions` 含 `https://*.aliyuncs.com/*`。

## 权限

```json
"permissions": ["storage", "tabs", "downloads", "scripting"]
```

- `storage`：session/local 设置
- `tabs`：读取当前标签页、打开编辑器标签页、返回商品页
- `downloads`：导出 PNG
- `scripting`：页面在扩展安装前已打开时补注入 content script；以及**把回填脚本注入到商品页**
  （`executeScript({ files })` —— 这是唯一能把经典脚本注入非顶层 frame 的方式）

未使用 `<all_urls>`、未使用 `cookies`（登出走服务端 `/api/auth/logout`）；也**未使用
`web_accessible_resources`** —— 回填脚本靠 `executeScript` 注入，不需要暴露给页面。

`host_permissions` 只覆盖扫描链路真正会用到的域，与 `content_scripts.matches` 对齐：

```json
[
  "https://*.aliexpress.com/*",          // 卖家后台商品页（与 content_scripts.matches 同一套规则）
  "https://*.aliexpress-media.com/*",    // 商品图 CDN
  "https://*.alicdn.com/*",              // 商品图 CDN
  "https://39.107.244.239/*",            // 自建服务端（登录 / 上传 / 抠图）
  "https://*.aliyuncs.com/*"             // 抠图结果可能落在 OSS
]
```

`aliexpress.us` 等地区站点**未**申请：扫描器只认 `aliexpress.com` 卖家后台，授予了也进不来，
属于死授权（早期版本误加，已移除）。若将来要支持其他地区站点，必须同时改
`src/shared/page-gate.ts`、`content_scripts.matches` 与页面适配器的路径判定，只加 host 权限是不够的。

## 已知限制（第一版）

1. 仅支持 AliExpress 卖家后台商品编辑页的**商品图片控件**（主图 + 更多图片，见上文「提取范围」）；不做详情图 / SKU 图 / 视频封面 / MutationObserver 自适应扫描。`aliexpress.us` / `.ru` 等地区站点会**明确提示不支持**（`src/shared/page-gate.ts`），而不是静默失败。
2. 扫描到的主图**全部默认 `selected = true`**，暂不支持逐张勾选。
3. 抠图并发为 6（`CUTOUT_CONCURRENCY`）。已用 6 张各不相同的图片实测线上服务：6/6 全部成功，
   墙钟 5.6s（单项耗时累加约 19.8s，说明确实是并行而非排队）。但这是**小型图片**下的结果，
   大图同时上传 6 张时的表现尚未测量；若遇到超时，把该值调小即可。
4. 水印框只在有默认水印时自动注入；草稿水印的显示状态不跨刷新保存（刷新后回到默认水印）。
5. 登录态是浏览器会话级 Cookie，浏览器完全退出后需重新登录（选项页可自动重登）。
6. 抠图失败仅影响该张图片，界面提供「重试」；失败的图片不阻塞导出。
7. 未实现：自动上传（无点击自动补图）、Session TTL、孤儿 Blob GC、schema migration、SHA-256 缓存、retry backoff。
8. 回填是**半自动**的：需要你在编辑器里点「回填到商品页」。找不到可点击上传入口时**不做全自动兜底**，
   而是分两种情况给不同的指引：图片位全满 → 报错让你先删一张；有空位但入口找不到（页面改版）→
   让你手动打开上传面板（打开后再点一次回填会复用该面板继续，不会卡在同一个错误上）。
   回填只从**最后一个空槽位**的入口开面板，新图追加到末尾；没有空槽位入口时直接拒绝，
   绝不点击已占用槽位上的入口（那会覆盖旧图）。除非你关掉「回填前删第 1 张」，
   否则它会先删掉原来的第 1 张来腾空位 —— 所以默认那一条**不是**「旧图全都还在」。
   删图不可撤销，本流程也不会替你保存，删掉的那张需要你手动补回。
9. 文字图层只做基础排版：内容 / 字体（仅本机字体）/ 字号 / 颜色 / 加粗 / 左中右对齐 / 描边 / 阴影。
   不含渐变、曲线文字、富文本、每字符不同颜色、字体上传与网络字体，也不做多层描边或内发光。
   属性在失焦时才提交，所以输入过程中画布不会逐字实时刷新（描边 / 阴影同理）。
   文字的可见大小是 `字号 × 缩放`；用手柄缩放会自动折算成字号，但字号上限 200，
   超出上限的那部分只能留在缩放里、**不进样式记忆**（下次新建最多沿用 200）。
10. 本地图片只有**文件选择器**与**剪贴板粘贴**两个入口，不做拖拽上传；粘贴只取位图，
    不处理「粘贴一个图片 URL / HTML 片段」。上传后不能删除素材，也无法给素材改名。
    单张上限 20MB（`MAX_UPLOAD_BYTES`）—— 抠图服务端本来就缩到 1600px，再大只是白等一次写盘。
11. 镜像 / 旋转**只作用于当前选中的那一个图层**：不支持框选或多选后一起变换，也没有「整张画布转 90°」。
    角度归一化到 `[0, 360)`，所以左右各转 90° 转满一圈不会累积成 360°。
